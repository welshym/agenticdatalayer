Business Context Layer — Overview

A runnable demonstration of an agentic data-access layer for a Telco. It turns raw records from disconnected Systems of Record into a single clean, governed "context packet" that any AI agent can read — and routes every write through a permission-gated broker with a full audit trail.

The four architectural layers

Agentic layer

Agent Context Gateway (ACG)

:8013

The single entry point agents use to READ context. Cache-first retrieval, pydantic-graph plan, MCP SSE server, compatible-offers endpoint.

Agentic layer

Action Broker

:8018

The single entry point for WRITES. JWT auth, permission gate, payload validation, immutable audit, forwards to the SoR.

Business Context

CDC Assembly

:8011

Consumes raw SoR events, applies ontology field mappings, performs a stateful cross-domain join (30s timeout → partial).

Business Context

Context Cache

:8012

Two tiers — a permanent store (all known customers, never evicted) plus an evictable hot cache.

Business Context

Offer Engine

:8016

Walks the product catalogue graph to compute commercially compatible next-best offers.

Systems of Record

CRM · Catalogue · Billing

:8010 · :8014 · :8017

Mock source systems for identity, product master data and subscriptions. They emit change events on update.

Cross-cutting

Logging Service

:8015

Structured assembly log — every decision the pipeline makes is traceable per customer.

Key capabilities

🧩

Canonical context assembly

Heterogeneous SoR fields are mapped to one canonical schema via ontology.py. Agents never see SoR-specific field names or know which systems exist.

⚡

Cache-first reads

Served from the hot cache or permanent store; on-demand assembly only when needed. Each response tags its retrieval_source.

🔗

Event-driven CDC

SoR changes emit events; CDC joins the CRM + Billing domains within a 30-second window, producing complete or partial_timed_out assemblies.

🛡️

Governed writes

The Action Broker checks the caller's declared permissions, validates the payload against the write-route schema, and only then forwards to the SoR.

📜

Immutable audit

Every write intent — permitted or denied — is recorded in an append-only audit log with the decision and reason.

🎯

Compatible offers

The Offer Engine returns only commercially valid upsell / cross-sell products for a customer's current holdings.

🔌

MCP SSE server

ACG exposes a Model Context Protocol endpoint so agent runtimes connect and stream context over SSE.

🕐

Freshness & provenance

Each packet carries an assembled-at timestamp, source systems, applied field mappings and a version — full lineage.

The Explorer tab

The Explorer tab is a hands-on console: pick a customer to load their assembled holdings via the ACG, inspect the raw CRM & Billing records, publish CRM change events, and add / update / cancel billing subscriptions — watching the pending-assembly queue, structured log trace and ontology provenance update in real time. It also includes quick Test Scenarios and a View API Docs button.

API surface

Agent Context Gateway — reads

  • GET /context/{id} — execute the retrieval plan and return the assembled context packet
  • GET /compatible-offers/{id} — held products plus commercially compatible offers
  • GET /cache-status — population of both cache tiers
  • GET /retrieval-plan · /ontology — introspect the plan graph and assembly spec
  • GET /mcp/sse — MCP streaming endpoint for agent runtimes

Action Broker — writes

  • POST /token — issue a demo JWT for a named client (e.g. ui-client, purchase-agent)
  • POST /submit-intent — submit a governed write intent
  • GET /permissions · /write-routes — introspect what each caller may do
  • GET /audit — the immutable audit log

How it's deployed

Packaged as a container and run on AWS ECS Fargate behind an Application Load Balancer (account 054663422011, us-east-1). Every resource is tagged Project=BCL; image pulls go over private VPC endpoints (ECR / S3 / CloudWatch Logs).
